# MVP 技术方案

采用 Node.js 22+ 内置 HTTP 服务与原生浏览器 ES Modules，无构建步骤、无运行依赖。仅本机监听。浏览器负责交互与本地保存，服务端提供静态文件和 `/api/reading` 转发，不保存用户会话或 API Key。

- `public/cards.js`：完整 78 张牌、固定 ID、中文名称与各自的正逆位基础牌义。
- `public/core.js`：使用 Web Crypto 随机数的 Fisher–Yates 洗牌，循环切牌，显式流程状态与一次补牌限制；提示词带全量原问题、牌阵、牌面和已完成对话。
- `public/app.js`：事件驱动界面；每次动作本地保存，未完成调用保留 pending 请求供刷新后重试。异步请求期间禁止切换、删除、另起会话和重复提交。失败不改变牌面或消耗第二次补牌。
- `server.mjs`：验证配置、请求大小与来源，非流式 Chat Completions，60 秒超时，重定向拒绝、中文分类错误、响应内容验证与密钥回显脱敏。密钥只通过请求体进入本地服务，再放入上游授权头；不记录请求内容和上游错误文本。
- 存储：`tarot.journal.v1` 保存会话数组与当前 ID；`tarot.config.v1` 保存地址和模型，记住密钥时才加入 Key。会话包含版本、时间戳、牌堆顺序、切牌位置、状态、选牌／方向／翻开状态、补牌额度、模型、提示词版本和对话。
- 页面采用米白纸张与柔和绿，横向可滚动弧形牌扇，移动端布局与减少动画偏好；模型回答先转义 HTML，再显示安全的加粗标记，避免执行返回的 HTML。

测试分为牌库与状态机测试、本地存储及上下文测试、HTTP 转发集成测试和浏览器验收。真实模型的叙事质量不由程序测试替代。

## 手札书页界面

- `public/journal.js`：独立章节可用性与恢复入口、长文本分页、对话页码和角色关联。未开始抽牌不能跳过仪式，待补牌与待手动开始解读恢复到抽牌章。
- 桌面使用双页书册布局、书脊与纸页边缘，顶部四章导航和轻量翻页过渡；手机使用单页布局。主界面固定于视口，各章互相独立，长解读与历史通过上一页／下一页阅读。极长单段等边界内容允许在当前书页内滚动。
- 模型连接用右上角按钮和原生 dialog，保存时校验并持久化，关闭或 Escape 取消未保存的修改；取消记住密钥立即清除保存的 Key。沿用原配置与会话存储键，不迁移或丢失既有记录。
- 各章切换保留追问草稿；请求失败在来信页内显示原因和重试入口。分页只影响展示，模型请求仍携带完整会话上下文。

## 邀请码上线体验版

- `server/hosted.mjs`：校验生产配置、固定可信模型地址、签名 Cookie 邀请会话、登录与调用频率限制、全站与单码并发限制、额度持久化；本地模式保持独立，禁止在生产环境退回公开自填 Key 代理。
- `UsageStore` 用单进程队列串行预留额度，成功写入临时文件并同步、原子替换后再发起模型调用。计数按邀请码 SHA-256 保存，带每日与累计、全站每日与累计四重上限；每日按北京时间零点重置。额度损坏或不可写时拒绝调用。仅用于单实例部署，扩容需改为共享事务存储。
- `/api/runtime` 只返回运行模式和模型名；`/api/access` 负责邀请码登录、状态和退出；`/api/reading` 在线上忽略浏览器配置，只使用服务端密钥和固定模型；服务端重新附加固定系统提示，约束输入与输出长度。`/healthz` 检查服务和额度存储就绪。
- `public/access.js` 分离两种请求载荷，上线模式只发送对话，Cookie 自动随同源请求携带，不包含 API Key、目标地址或明文邀请码；浏览器按运行模式显示本地模型设置或邀请码与额度弹窗。
- Cookie 为七天、HttpOnly、SameSite=Strict，公开部署为 HTTPS 且带 Secure。域名与来源按 `APP_ORIGIN` 校验；服务端不跟随上游重定向，不反射原始上游错误。失败生成保守计次，避免重试绕过预算。
- `render.yaml` 配置 Node 24、健康检查、构建时运行全部测试、单实例和持久化磁盘；部署需要用户在平台填写密钥及邀请码并确认平台费用。源码不含真实上线密钥。详见 [部署说明](DEPLOY.md)。
