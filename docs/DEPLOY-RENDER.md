# 邀请码体验版部署

访客只输入邀请码，模型服务统一由站点提供。API Key、模型地址、邀请码列表与会话签名密钥均配置在服务端，不进入前端代码或浏览器本地历史。原来的本地自填 Key 模式仍可单独运行。

## 1. 默认体验规则

| 项目                   | 默认值 | 环境变量                    |
| ---------------------- | ------ | --------------------------- |
| 每个邀请码每日生成次数 | 5      | `TAROT_INVITE_DAILY_LIMIT`  |
| 每个邀请码累计生成次数 | 20     | `TAROT_INVITE_TOTAL_LIMIT`  |
| 全站每日生成次数       | 100    | `TAROT_DAILY_LIMIT`         |
| 全站累计生成次数       | 1000   | `TAROT_TOTAL_LIMIT`         |
| 每个邀请码每分钟请求数 | 2      | `TAROT_REQUESTS_PER_MINUTE` |
| 全站同时生成数量       | 3      | `TAROT_CONCURRENT_LIMIT`    |
| 单次输入字符数上限     | 20000  | `TAROT_MAX_INPUT_CHARS`     |
| 单次输出 token 上限    | 2048   | `TAROT_MAX_OUTPUT_TOKENS`   |

每日额度在北京时间零点更新。全站或邀请码的每日／累计额度任一耗尽即停止生成。一个邀请码在不同设备使用时共享额度；清除浏览器数据、退出或重新输入邀请码不能重置额度。

抽牌、翻页、看历史不计次数。通过校验并进入模型调用的请求先持久化扣次；即使上游超时或返回异常，也不返还次数，因为可能已经产生模型用量。重试另计一次。无效邀请码、输入格式错误和超长输入不扣生成次数。次数与单次长度是用量上限，不等同于固定金额上限；还可在模型服务平台设置消费限额。

会话通过 HttpOnly、SameSite=Strict Cookie 保存七天；公开 HTTPS 部署额外使用 Secure Cookie。无需注册账号。历史仍仅存在各自浏览器，不跨设备同步。

## 2. 准备服务端配置

需要你自己的模型服务 API Key，不要把真实密钥写入 Git、前端源码或聊天。运行：

```sh
npm run create-secrets
```

工具生成一个随机邀请码列表和会话签名密钥，直接复制到部署平台的环境变量中。每个邀请码至少 16 字符，支持最多 100 个互不相同的邀请码。给不同朋友分配不同邀请码；添加更多邀请码可再次运行生成工具，将新值加入原 JSON 列表。不要因此覆盖已在用的会话签名密钥。

必填配置：

- `TAROT_MODE=hosted`。
- `TAROT_API_BASE_URL`：可信模型服务的 HTTPS 基础地址，只由站点维护者设置。
- `TAROT_API_KEY`：站点统一使用的模型密钥。
- `TAROT_MODEL`：准确的模型 API 名称。
- `TAROT_INVITE_CODES`：JSON 数组，如 `["你生成的随机邀请码"]`。
- `TAROT_SESSION_SECRET`：至少 32 字符的独立随机签名密钥，使用上述工具生成。
- `TAROT_USAGE_FILE`：持久化磁盘内的额度记录路径。
- `APP_ORIGIN`：唯一允许的网站根地址，例如 `https://你的域名`。在 Render 默认域名上可不设，程序自动使用 `RENDER_EXTERNAL_URL`。

邀请码及签名密钥也属于服务端配置，不在日志中输出。取消某人的访问：从 `TAROT_INVITE_CODES` 中删除对应邀请码后重新部署，其旧 Cookie 即失效；重新加入相同邀请码会沿用原额度记录。

默认的 DeepSeek 官方接口在线上模式关闭思考，让输出额度用于短篇来信；其他兼容服务不附带这个专有参数。本地模式保持原行为。参数依据见 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

## 3. 部署到 Render

仓库提供 [render.yaml](../render.yaml)，包含 Node 24、健康检查、构建时全部测试和单实例持久化磁盘。这个配置选用付费 Starter 服务与磁盘；创建时在平台查看实际费用，再确认购买。本次代码改造不创建或购买云服务。

1. 将仓库推送到你的 GitHub 仓库，建议保持私有。
2. 在 Render 创建 Blueprint，连接仓库并加载 `render.yaml`。
3. 按提示填写 `TAROT_API_KEY` 和 `TAROT_INVITE_CODES`；签名密钥由平台生成。可修改模型地址、模型名和各项额度。
4. 保持单实例，额度文件路径为 `/var/data/tarot/usage.json`，对应持久化磁盘挂载点 `/var/data/tarot`。
5. 创建服务后，构建执行 `npm test`，全部通过才启动 `npm start`。检查 `/healthz` 返回 `{"status":"ok"}`。
6. 用分配的 HTTPS 地址打开网页，输入邀请码，验证一次完整抽牌与解读。后续提交到关联分支会触发测试和部署。
7. 如绑定自定义域名，将 `APP_ORIGIN` 改成该 HTTPS 域名。域名变更后需重新输入邀请码；浏览器历史也按新域名独立保存。

配置使用平台端口 `PORT` 并监听 `0.0.0.0`。页面和接口只接受配置的正式域名，转发兼容平台的 HTTPS 入口，不接受访客自定义模型地址或密钥，也不跟随模型服务重定向。

Render 磁盘仅保存挂载路径下的数据，并限制服务为单实例。详情见 [Web Services](https://render.com/docs/web-services)、[Persistent Disks](https://render.com/docs/disks) 和 [Blueprint 规范](https://render.com/docs/blueprint-spec)。

## 4. 额度保存与运维

额度记录只包含邀请码的 SHA-256 标识、日期和计数，不保存明文邀请码、问题、牌面、对话或 API Key。写入时先写临时文件并同步，再原子替换；成功持久化后才允许调用模型。损坏、无法读取或无法写入时停止调用，避免默默重置预算。

本版适合单实例小范围邀请体验：只运行一个应用进程，不能用集群、多副本或多个服务共享同一份额度文件。需要扩容时应先迁移到支持事务的共享数据库。不要删除额度文件或更换到空白磁盘，否则累计记录会丢失。应定期备份该文件；恢复更早备份也会回退计数。

模型 API Key 轮换在环境变量中进行。额度异常时先停用邀请码或调低全站限制，查看磁盘与配置；程序不会输出密钥或上游错误详情。`/healthz` 只报告服务与额度存储是否就绪，不返回配置。

## 5. 本地检查上线模式

本地默认仍为自填模型模式，已有会话和配置不迁移。想试邀请码模式时：

```sh
cp .env.example .env
```

在 `.env` 中填入真实的服务端配置；示例只允许本机地址 `http://127.0.0.1:3000`。运行：

```sh
npm run check:deployment
npm start
```

检查命令验证配置与额度文件可用性，不调用模型。公开地址必须使用 HTTPS；`NODE_ENV=production` 不允许退回本地自填 Key 模式。`.env`、其他环境文件及 `.data/` 都已忽略，不会被提交。结束本地邀请码测试后移走 `.env`，即可恢复原本地模式；使用应用期间保持服务运行。
