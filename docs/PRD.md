# 塔罗抽牌与 AI 解读 Agent — MVP PRD

- 版本：v0.1
- 整理日期：2026-11-06
- 状态：MVP 已实现并通过本地验收，详见 [验收记录](ACCEPTANCE.md)
- 依据：本轮需求访谈；竞品分析见 [prior_art.md](prior_art.md)

## 1. 产品目标

提供一个在本地运行、通过浏览器使用的塔罗抽牌与 AI 解读工具。用户围绕一个具体问题，完成接近线下体验的洗牌、切牌、选牌和翻牌仪式，再获得沉浸式解读，并围绕同一组牌继续追问。

MVP 优先验证两件事：

1. 抽牌流程有参与感，操作清楚且顺畅。
2. 解读与追问能够结合用户的问题和既定牌面，保持连续性。

不以预测结果的准确率作为验收指标。

## 2. 已确认的 MVP 范围

| 模块 | 范围 |
|---|---|
| 使用入口 | 本地运行的网页，兼顾电脑和手机浏览器，无需注册登录 |
| 牌组 | 完整 78 张经典韦特牌，支持正位和逆位 |
| 牌阵 | 单张牌；现状／阻碍／建议；过去／现在／未来 |
| 抽牌仪式 | 默念问题 → 顺逆时针绕动洗牌 → 点击切点并合拢两叠 → 弧形扇面铺牌 → 手动选牌 → 逐张点击翻开；可选摄像头手势 |
| 开始解读 | 所有牌翻开后，用户点击“开始解读” |
| 解读风格 | 沉浸叙事，像塔罗师围绕用户的问题讲述连贯故事 |
| 对话 | 支持围绕当前问题与牌面继续追问 |
| 补牌 | 可选择补抽一张；每次解读最多补抽一次；从剩余牌中抽取 |
| 模型接入 | 用户填写兼容 OpenAI 的 API 地址、API Key 和模型名 |
| 密钥保存 | 默认不保存 API Key；用户可主动选择“记住密钥” |
| 历史 | 保存在当前浏览器，支持恢复、查看和删除 |
| 视觉 | 温暖手札风格：米白纸张、柔和色彩、轻量动画 |

## 3. 核心用户流程

### 3.1 首次使用与模型配置

1. 用户打开本地网页。
2. 填写 API 地址、API Key 和模型名。
3. 可主动勾选“记住密钥”，默认不勾选。
4. 输入本次问题，选择一种牌阵，进入抽牌流程。

配置缺失时，提示需要补充的字段。普通使用过程不要求用户了解 Agent 编排或提示词等实现细节。

### 3.2 首轮抽牌与解读

```text
输入问题、选择牌阵
        ↓
提示用户默念问题
        ↓
顺逆时针绕动洗牌
        ↓
选择切牌位置并完成切牌
        ↓
牌背以弧形扇面展开
        ↓
用户逐张选牌，放入对应牌位
        ↓
用户逐张点击翻开
        ↓
全部翻开后，点击“开始解读”
        ↓
AI 给出沉浸式解读
        ↓
继续追问，或补抽一张后继续解读
```

### 3.3 追问与补牌

- **直接追问：**沿用原问题、原牌阵、已抽牌和当前对话回答，不重新抽牌。
- **补抽一张：**由用户主动选择；从当前未抽出的牌中手动选取并翻开，再用于回应追问。
- 补牌后，后续追问使用全部已抽牌：单张牌阵共两张，三张牌阵共四张。
- 一次解读会话中最多补抽一张，补牌后不可再次补抽。
- AI 不自行补牌，不擅自更换已有牌面。

### 3.4 历史与恢复

- 用户可以查看历史问题、牌阵、牌面、解读和追问。
- 刷新后能够恢复当前会话，避免丢失已选牌与已完成内容。
- 打开历史记录后，可以围绕该次解读继续追问；补牌额度沿用该记录的状态。
- 支持删除单条历史记录。
- 历史仅存在当前浏览器，不提供跨设备同步；清除浏览器站点数据会丢失记录。

## 4. 功能需求

### 4.1 问题与牌阵

| 牌阵 | 抽牌数量 | 牌位 |
|---|---:|---|
| 单张牌 | 1 | 针对当前问题的单张指引 |
| 现状／阻碍／建议 | 3 | 现状、阻碍、建议 |
| 过去／现在／未来 | 3 | 过去、现在、未来 |

- 问题不能为空。
- 在开始抽牌前选择牌阵。
- 抽牌开始后，问题与牌阵作为本次会话的固定信息保存；更换问题或牌阵需开始新会话。
- MVP 不增加 AI 自动选牌阵、自动澄清问题或额外背景问卷。

### 4.2 洗牌、切牌与选牌

- 使用完整 78 张牌进行程序随机洗牌，抽牌结果由程序决定。
- 每张被抽出的牌随机决定正位或逆位，并在确定后保存。
- 切牌位置必须影响本次牌堆的实际顺序，不能仅播放装饰动画。
- 牌背以弧形扇面展开；支持横向滑动浏览和点击选牌。
- 选牌前不暴露牌名、牌面或正逆位。
- 按选择顺序依次填入牌阵位置，不允许重复选择同一张牌。
- 达到所需数量后停止选牌，进入翻牌阶段。
- MVP 采用点击与轻量动画，不实现自由拖拽或复杂物理模拟。

### 4.3 翻牌

- 已选牌先以牌背放入对应牌位。
- 用户逐张点击翻开；翻牌只展示牌面，不触发逐牌 AI 解读。
- 牌名、牌位和正逆位标识清楚可见。
- 所有牌翻开前，“开始解读”不可用；全部翻开后允许用户主动开始。
- 翻开后的牌不允许重新抽取或修改正逆位。

### 4.4 AI 首轮解读

模型输入至少包含：用户问题、牌阵、牌位、已抽牌、正逆位及对应基础牌义。

输出要求：

- 使用中文，保持温暖、有仪式感的沉浸叙事风格。
- 结合用户的具体问题讲述牌面含义，避免仅复述通用牌义。
- 单张牌阵围绕该牌展开；三张牌阵需体现每个牌位及牌与牌之间的联系。
- 可以分段，但不强制展示为机械的字段或表格。
- 提供与当前问题相关的建议，并保留用户自主判断的空间。
- 不编造用户未提供的经历，不将牌面解释说成确定事实或必然发生的预测。

等待期间显示明确状态；完成后开放追问。无需多 Agent 审稿或复杂的生成阶段展示。

### 4.5 对话与补牌

- 追问时保留本次问题、原牌阵、所有已抽牌及必要对话上下文。
- 回答聚焦当前追问，不必每次重述完整首轮解读。
- 用户可选择直接追问，或补抽一张后解读。
- 补牌显示为独立的“补充指引”位置，不替换原有牌。
- 补牌同样支持正逆位，并通过用户手动选牌、点击翻开的方式呈现。
- 补牌后解读失败，重试必须复用该补牌，不再次消耗额度或重新抽牌。

### 4.6 模型配置与密钥

- 配置项：API 地址、API Key、模型名、“记住密钥”。
- 默认不持久化 API Key，仅当前页面使用；刷新或关闭后需重新填写。
- 勾选“记住密钥”后，允许将密钥保存在当前浏览器；取消时移除已保存密钥。
- API 地址与模型名可保存在当前浏览器，减少重复配置。
- 未提供密钥或密钥失效时，明确提示补充或修改，不使用项目内置付费密钥。
- 历史记录、导出式内容和错误信息不得夹带 API Key；日志不得记录密钥。
- 页面需说明：生成解读需要联网，请求中的问题与牌面等内容会发送至用户配置的模型服务。

### 4.7 会话与本地保存

最小保存内容：

- 会话 ID、创建与更新时间。
- 用户原问题、牌阵与当前流程状态。
- 恢复抽牌所需的牌堆顺序、切牌状态、已选牌与翻牌状态。
- 牌 ID、牌位、正逆位及补牌使用状态。
- 已完成的解读、追问及回答。
- 模型名和必要版本信息；密钥与会话记录分开保存。

历史以“一次问题与抽牌会话”为单位组织。模型调用失败或重新生成回答，不应创建一份新牌面。

### 4.8 异常处理

- 配置错误、连接失败、超时或模型返回异常时，显示可理解的提示并允许重试。
- 重试复用已确定的问题、牌面与正逆位。
- 调用中避免重复提交造成多次请求。
- 刷新或中断后，不将未完成的解读标为成功；保留已完成内容与牌面，允许重新生成。
- 不用未标明来源的模板文字冒充 AI 成功解读。

## 5. 页面与视觉

只需覆盖以下界面区域，具体是否拆成独立页面由实现决定：

1. **提问与配置：**模型配置、问题输入、牌阵选择。
2. **抽牌仪式：**默念提示、洗牌、切牌、扇面选牌、牌阵翻牌。
3. **解读与对话：**当前牌阵、AI 解读、追问输入、补牌入口。
4. **历史记录：**列表、详情、继续追问、删除。

视觉采用米白纸张背景、柔和色彩及手札式排版。牌面、正文与操作入口保持清晰；动画服务于洗牌、选牌、翻牌的参与感，不增加操作负担。

电脑与手机都应能够完成全部流程；移动端扇面牌可横向浏览，正文易于阅读，主要操作支持触控。

### 5.1 手札书页交互（2026-11-06 调整）

- 各模块改为书页形式，顶部切换“写下心事／抽牌仪式／牌间来信／往日手札”，不把全部模块排成长条页面。
- 桌面双页书册，移动端单页；长解读和历史分页阅读，支持轻量翻页过渡与减少动画偏好。
- “模型连接”缩为右上角按钮，点击弹出设置对话框；配置保存后自动恢复，修改时才需再次打开。密钥仍仅在主动选择记住后持久化。
- 页面重排不改变既有牌面、手动补牌规则或历史数据；切换章节保留追问草稿。

## 6. MVP 不包含

- 公网部署、账号注册、会员与支付。
- 云端历史、跨设备同步、长期用户画像。
- 其他牌组、自定义牌阵、复杂十张牌阵。
- 自动选牌阵、AI 自主补牌、无限补牌。
- 多 Agent 协作、向量数据库、复杂检索系统。
- 复杂刚体物理效果和完整 3D 场景；手动绕动与可选摄像头仪式已补充实现，见 [手势仪式说明](RITUAL.md)。
- 语音、社交分享、主动提醒、独立反馈或评测管理页面。

竞品分析中的拓展建议不自动纳入本次 MVP。

## 7. 验收标准

| 场景 | 通过标准 |
|---|---|
| 三种牌阵 | 单张抽 1 张；两种三张牌阵各抽 3 张，牌位对应正确 |
| 仪式完整 | 能依次完成默念提示、洗牌、切牌、扇面选牌与逐张翻牌 |
| 切牌有效 | 切牌会改变实际牌堆顺序 |
| 抽牌正确 | 同一会话中无重复牌，正逆位确定后保持不变 |
| 手动开始 | 未全部翻开时不能开始解读；全部翻开后由用户主动启动 |
| 解读相关 | 不说错牌名、牌位或正逆位，能结合问题形成连贯叙事 |
| 追问连续 | 回答沿用当前问题与牌面，不无故重抽或篡改已有信息 |
| 补牌限制 | 最多补抽一张；不与原牌重复；后续追问能使用补牌 |
| 重试稳定 | 解读或补牌解读失败后重试，牌面与补牌额度不变化 |
| 本地恢复 | 刷新后恢复已确定的牌面与已完成内容；未完成请求可重试 |
| 历史管理 | 能查看、继续追问和删除历史；删除后不再显示 |
| 密钥行为 | 默认刷新后不保留；主动记住后可恢复；取消记住后清除 |
| 移动端 | 能触控完成全部操作，无影响使用的布局溢出或遮挡 |
| 运行方式 | 有清晰的本地启动说明，用户可在浏览器中打开并完成主流程 |

## 8. 实现边界与默认细节

本节为基于已确认需求补充的最小实现约定，不新增产品模块：

- 单张牌的牌位默认称为“单张指引”。
- 选牌顺序对应牌位顺序；开始新会话才允许更换问题和牌阵。
- 补牌沿用剩余牌堆，提供简化的扇面选牌与手动翻牌，不强制重走完整仪式。
- 正位和逆位默认各 50% 概率；使用标准洗牌算法，避免随机比较器排序。
- 模型对话采用一条受控流程即可；接口地址规范、上下文长度与异常处理策略在实现时保持简单。
- 牌面素材应记录来源和适用授权，不能因源代码开源而默认牌面图片也适用同一许可。
- 产品以娱乐和自我反思为定位，不替代专业判断。

## 9. 实现优先顺序

1. 跑通问题、牌阵、独立抽牌、手动翻牌和单次模型解读。
2. 补齐洗牌、实际切牌、扇面选牌的完整仪式体验。
3. 接入连续追问、一次补牌、本地历史与恢复。
4. 验证错误重试、密钥保存、移动端操作，并完善温暖手札视觉。

以上全部完成并通过验收，才视为本次 MVP 完成。

## 10. 邀请码上线体验版（新增范围）

用户确认采用“打开即用＋邀请码＋调用次数限制”的发布方案，在原本地 MVP 上新增：

- 由站点维护者在服务端配置统一模型服务，访客无需提供 API Key。保留原本地自填 Key 模式。
- 邀请码开启体验，自动保存安全会话；右上角入口显示体验额度并支持退出。不同邀请码独立计数，同一邀请码跨设备共用额度。
- 默认每码每日 5 次、累计 20 次，全站每日 100 次、累计 1000 次；支持调整。每次生成或重试计一次，已进入上游调用的失败不返还。
- 服务端持久化额度，浏览器刷新、退出、重启不重置；每日额度按北京时间零点更新。限流、并发和输入输出上限在服务端执行，超限后仍可查看已有历史与牌面。
- 支持 HTTPS 正式域名、平台端口、健康检查和 Render 单实例部署。模型请求仅发往维护者配置的固定地址。
- 不新增注册账号、支付或云端对话历史。邀请码、额度与部署配置属于新增发布范围，原牌面、补牌限制和书页交互保持。
